=== flared: lifecycle ===
* cluster::_reconcile_wal_follower_locked() runs after every accepted node map and on every change of the flag:
  an ACTIVE SLAVE on a RocksDB backend follows its partition's master; a master, a proxy, a preparing slave or a
  partition without a master does not. A follower that declared needs_rebuild is NOT restarted on the same source —
  the rebuild path (demote -> hold -> reseat) cycles the node's role, and that cycle is the fresh start.
* Options (dynamic, all OFF/bounded by default): repl-follow-enabled=false, repl-follow-max-batches=256,
  repl-follow-max-bytes=4194304, repl-follow-poll-interval-usec=200000. The follower applies only through the common
  rule, so it must not be enabled before repl-identity-forward is on cluster-wide (stated in the option help).
* flared stops the follower before telling the index it is leaving, so no batch lands on a node that is shutting down.
* stats gains repl_follow_enabled so the operator can tell the mode from the state.

=== operator: ownership (design §5.4) ===
* A drop observed for a destination whose own stats say the follower owns it (repl_follow_enabled=1 and state in
  following/initial_sync/disconnected/error) is RECORDED and HELD with the reason "owned by continuous replication"
  and the bar it must reach — the master's rocksdb_latest_sequence_number at observation, which the dropped write is
  at or below. No demotion, no reconstruction. plan() never acts on an owned entry, gate open or not.
* Closing needs the follower to be `following` (a disconnected follower's position is stale by definition), a recorded
  bar, and repl_applied_lsn at or past it: REPLICA REPAIR CLOSED by continuous replication, without a rebuild.
* needs_rebuild, the mode going off, or UNREADABLE stats end ownership and hand the entry — drops and node key kept —
  to the ordinary path. Unreadable stats never CLAIM ownership: fail closed to the path that does not depend on them.
* A drop while the mode is on but the follower is `disconnected` is still owned: the follower resumes from its
  position; starting a reconstruction there would be the blip-costs-a-rebuild failure this work exists to remove.

=== NOT executed / still open ===

* Eligibility for reads/promotion/deletion (design §5.3) is NOT implemented: the operator does not yet read
  repl_follow_state for those decisions, and a WAL-mode replica is not yet removed from the read set by the operator —
  today that has to be done by configuration. Recorded as the remaining SAF-10c item.
* The wire handshake (EPOCH / MORE / epoch_mismatch) still has unit coverage of the decision table only.
